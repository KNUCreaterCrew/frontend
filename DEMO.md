# 시연 점검과 기록

시연 전에 확인할 것과 확인한 결과를 적는 문서입니다. 확인하지 않은 칸은 `미확인` 으로 둡니다.

## 1. 시연 주소와 QR

| 항목    | 값                                                                                                                            |
| ------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 웹 주소 | https://zeroframe-web.onrender.com                                                                                            |
| QR      | [`docs/qr/zeroframe-web.svg`](docs/qr/zeroframe-web.svg), 발표 자료용 [PNG](docs/qr/zeroframe-web.png) (카메라 스캔은 미확인) |
| 백엔드  | https://zeroframe-backend-p1wa.onrender.com                                                                                   |

QR 이 여는 주소는 `/`(방 목록)입니다. 웹 주소가 바뀌면 QR 을 다시 만들고 백엔드 `render.yaml` 의 `CORS_ALLOW_ORIGINS` 도 고칩니다.

## 2. 시연 전 점검

확인한 항목에는 날짜와 근거를 붙입니다.

- [ ] 시연 전날까지 Render 의 자동 배포를 끄고, 끝나면 다시 켭니다(웹과 백엔드 모두). 그 뒤 Blueprint 를 다시 적용했다면 `render.yaml` 값(`checksPass`)으로 돌아갔을 수 있으니 다시 확인합니다.
- [ ] 시연 30분 전과 직전에 `https://zeroframe-backend-p1wa.onrender.com/health` 를 열어 백엔드를 깨웁니다.
- [x] CORS 를 확인합니다. 둘 다 `access-control-allow-origin: https://zeroframe-web.onrender.com` 이 붙어야 합니다. (2026-11-19 16:07 KST, 다른 출처에는 붙지 않고 POST 사전 요청은 거절되는 것도 확인)
  - [x] `curl -i -H "Origin: https://zeroframe-web.onrender.com" https://zeroframe-backend-p1wa.onrender.com/api/v1/rooms` → 200
  - [x] `curl -i -H "Origin: https://zeroframe-web.onrender.com" https://zeroframe-backend-p1wa.onrender.com/api/v1/rooms/NOPE` → 404
- [x] 휴대폰에서 `/` 와 `/rooms/IT4-101` 이 실서버 데이터로 뜹니다. (2026-11-19, iOS 카카오톡 인앱 브라우저, 3절 스크린샷)
- [ ] 휴대폰에서 `/rooms/IT4-101` 을 연 채로 새로고침해도 앱이 뜹니다. (호스팅이 이 주소에 앱을 돌려주는 것은 2026-11-19 `curl` 200 으로 확인, 휴대폰 새로고침은 미확인)
- [ ] 휴대폰에서 `/rooms/NOPE` 가 "방 없음" 화면입니다. (서버의 404 와 CORS 헤더는 확인, 화면은 미확인)
- [ ] iOS 와 Android 기본 카메라로 QR 이 열립니다.
- [ ] 장치(또는 demo 스크립트)의 보고가 들어옵니다.
